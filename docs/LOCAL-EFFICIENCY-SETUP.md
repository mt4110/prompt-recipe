# ローカルへの適用：Globalと個人設定

対象：自分のMac/PCを操作できる利用者、またはその環境で動くワーカー。

GitHub上のファイル追加、ローカル作業ツリーの更新、アプリのSQLiteへのImport、Global設定への統合は別の操作です。この文書の存在だけで、後三者が実施済みになることはありません。

## Globalを統合するワーカーへの依頼

次の依頼を、対象PCのPrompt Recipeリポジトリを開いたワーカーへ渡します。先にこの追加を含むブランチ・コミットの内容を確認してください。作業中の変更を消すcheckout、reset、clean、強制更新は不要です。

```text
このリポジトリのexamples/agents/resource-efficiency.mdを、実際に読み込まれるGlobal指示書へ統合してください。

1. 作業ツリーの未コミット変更と既存指示を読み取り専用で確認してください。現在のエージェント・CODEX_HOME・Globalの実ファイルを確認し、.agentという名称だけで保存先を決めないでください。
2. Codexでは通常$CODEX_HOME/AGENTS.md（既定は~/.codex/AGENTS.md）が候補です。AGENTS.override.mdがある場合は優先順位と運用意図を確認し、無視されるファイルへの追加やoverrideの新規作成で既存規則を隠さないでください。複数候補を解決できない場合だけ質問してください。
3. 既存の承認・セキュリティ・品質・作業言語・プロジェクト規則を保持し、同じ省資源ルールは重複させず統合してください。実質的に矛盾する既存規則の変更は確認を待ってください。Global全文を共有リポジトリやチャットへ転載しないでください。
4. 変更前にアクセス制限した場所へバックアップし、対象の版・内容が読取後に変わっていないことを確認してください。symlinkや共有dotfilesの管理元がある場合は無断で置き換えないでください。
5. 最小差分で保存し、再実行しても追記が増えないようにしてください。マーカーは同じ範囲の識別に使えますが、同範囲に人間の編集があれば丸ごと置換しないでください。本文中にPC固有パス・秘密・案件情報を追加しないでください。
6. 新しいセッションで、どの指示書が有効かと主要な原則を確認してください。確認のために追加の有料呼出しが必要なら、既存の利用条件に従ってください。権限・モデル・料金プランは変更しないでください。
7. 変更ファイル、統合した内容、重複整理、バックアップと復元方法、検証、未実施を報告してください。README等の詳細をGlobalへ全転載しないでください。
```

この操作はローカルのGlobalだけを対象とし、他のAI製品の設定を一括変更しません。ClaudeやCopilot等へ適用する場合は、その製品の読み込み先と優先順位を別途確認してください。既存のSkillやプロジェクト指示も一括複製しません。

## アプリへImportする

アプリで「台帳・セットをImport」を開き、`content/packs/resource-efficiency.json`を選択してプレビューを確認します。既存DBを削除したり、SQLiteを直接書き換えたりする必要はありません。アプリの既存の明示Importを使います。

Globalへ統合済みなら基本契約01を重ねず、その仕事のレシピだけを選択します。必要な組合せを名前付きセットに保存してください。全9件を初期セットへ強制登録しません。

個人の好みは台帳で別レシピにし、共通契約との差分だけを持たせます。たとえば「日本語」「開発・CS研究・防御的セキュリティが主用途」「承認済み反復は自律実行」「速度より品質を保った総費用を優先」です。実予算・氏名・PC固有パス・案件情報は公開パックに含めません。

## 確認と戻し方

Globalは新しいセッションで有効な読み込み先を確認します。戻す場合は現在の内容とバックアップを比較し、導入後の他の変更を消さない形で今回の差分だけ戻します。

アプリではまずセットから対象レシピを外せます。新しい空の作業領域と既存の作業領域で、Import・合成・コピー・再Import・個人編集・Exportを確認します。検証していない項目を完了と報告しません。

この変更にはMac実機操作やGlobal適用の実行記録は含みません。将来Built-inにする場合の条件はルートのTOKEN-EFFICIENCY.mdを参照してください。
