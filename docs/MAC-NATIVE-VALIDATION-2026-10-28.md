# Macのコピー・設定可能な小窓キーの確認

2026-10-28、macOS 27.0.1 / Apple Silicon、Node 26.9.0、Rust 1.99.1で確認。基準はv0.2.0、ショートカット設定と⌘Enter修正はその後の未公開変更です。公開済みv0.2.0のタグ・リリースは変更していません。

## 実装

- macOSの既定をOption+Space、Windows/LinuxはCtrl+Shift+Spaceとします。既存の保存値があればそれを優先します。
- 設定画面でプリセットかキー入力による記録を選び、「キーを変更して保存」で適用します。入力中はEscで記録をキャンセルできます。
- Rustが既存SQLiteのsettingsへ保存します。キーの正規化・検証はフロントとRustの両方で行い、通常画面だけが変更コマンドを実行できます。
- 新しい登録に成功してから古い登録を解除し、設定を保存します。登録失敗時は元の設定・登録を保持します。保存失敗時は新しい登録を解除して元の登録に戻します。復旧自体に失敗した場合も、登録済みと偽らず理由と画面のボタンによる代替操作を示します。
- 登録・解除とDB操作は直列化します。macOSメインスレッドへのディスパッチ待機中に、同じロックをUIスレッドが待つデッドロックを避けています。
- ヘッダー・初回案内・小窓は共通の設定から表記を生成し、変更イベントで別ウィンドウにも反映します。
- Control+Space、Control+Option+Spaceの入力ソース切替との競合を案内します。選択された組み合わせの警告判定もテストしています。
- ⌘Enterはプレビュー内にフォーカスがない場合にも有効にしました。表示中のプレビューだけを対象とし、登録ダイアログの背後・非表示ページ・IME変換中・キーリピートから誤コピーしないようにします。

- Rust57件: ライブラリ54件＋既存の統合試験3件。設定の保存・再読込み、正常切替、登録衝突で保存しないこと、保存失敗時の登録復旧、復旧失敗の明示、旧登録の解除失敗時の後始末、同じキーの再保存を含みます。衝突・ストレージ障害の試験はRegistryを差し替えた決定的な試験です。

- Tauriのrelease最適化した.app生成に成功。

## ネイティブの確認

テスト専用のアプリ識別子 `local.promptrecipe.nativeqa.v020` を使うrelease .appを生成し、既存の台帳・WebView設定と分離しました。UI操作はmacOSのアクセシビリティ経由で実施。クリップボードはNSPasteboardの実データを期待するダミー文字列と照合しており、ブラウザ内のスタブではありません。

| 項目 | 結果・範囲 |
| --- | --- |
| マスクコピー | 電話・メールをマスクした最終文字列がOSクリップボードと完全一致。日本語・改行・絵文字を保持 |
| 原文コピー | 元のダミー本文とOSクリップボードが完全一致 |

## macOSの競合検出の限界

使用するtauri-plugin-global-shortcut/global-hotkeyはCarbonのRegisterEventHotKeyを使用します。macOSは複数アプリでの共有登録を許す場合があります。別プロセスで同じControl+Option+Pを登録した試験でも、両アプリの登録が成功しました。したがって、登録成功を「ほかのアプリと競合しない」という保証にはできません。OS/APIが返す登録エラーは表示して復旧しますが、共有登録で発生する使い勝手の競合は利用者が別のキーを選ぶ必要があります。

アプリ宛ての自動キー送信と、実際のキーボードからのOS全体のホットキー入力は別の経路です。グローバル呼出しの最終確認には上記のユーザー操作を使いました。Windows/Linuxのアプリ実動作、あらゆるキーボード配列・他アプリの組合せ、配布用署名・公証を検証したものではありません。

記事用の録画にはダミー情報だけを使い、アプリのウィンドウ単位で収録しました。v0.2.0のコピー映像と、未公開のショートカット設定映像は区別します。録画ファイルはリポジトリへ含めません。

## 小窓の確認欄の追確認

- コピー前確認を本文プレビューより上へ移動し、選択後は入力欄（なければ見出し）へフォーカスするよう変更。検査待ちの状態も表示する。
- QA用Macアプリで「Mac」を検索→Enter選択し、確認欄とメールの検出候補が画面内に見えることを確認した。
- 見出しにフォーカスしたまま⌘Enterでコピーし、メールだけを `[MASKED]` にしたダミー文字列とNSPasteboardの内容が完全一致。電話には既存の個別無視設定が適用されていた。今回の試験開始前のクリップボードはメモリに退避し、全形式の復元一致を確認した。
- F1〜F24の表記関数はmacOSとWindowsの双方でFを保持する。新しい回帰テストで全範囲を確認。映像で指摘されたFの欠落は未再現で、変換関数を原因と断定していない。
- 英字「Mac」と日本語「入力」で小窓の検索結果が表示された。報告された約3秒のレインボーカーソルは未再現。操作ツールの所要時間をアプリ検索の処理時間とは扱わず、性能改善を実測したとは主張しない。
