## 使える流れ

初回は「レシピをひとつ知る → 自分の資料を指定してコピー → プロジェクトへ保存」の3段階。コピーは強制しない。案内はスキップでき、通常画面の「使い方を開く」から再表示できる。完了をローカル保存し、次回起動では通常画面を表示する。

通常画面にはプロジェクト／レシピ／改善の記録を配置。小窓は保存したアクティブプロジェクトとセットを使う。検索、矢印で候補移動、Enterで選択、Tabで変数入力、⌘Enterでコピー、Escで閉じる。

Rust側で変数展開・構造化制約検査・入力上限・プレビュー照合を実施。素材内の `{{...}}` は再展開しない。制約の矛盾、必須入力不足、会話環境と実行要求の不一致はコピーを止める。自由文の意味は未検査。教材本文を黙って削除・修正しない。

SQLiteは専用ワーカーが所有。入力値やコピー本文を利用記録へ保存せず、コピー成功後に操作IDと版IDのみ記録する。コピーとDB記録は別の処理なので、DB記録失敗は「コピー済み・記録失敗」と返す。クリップボード取得は素材変数がある場合の明示操作だけ。取得した素材は揮発状態に保ち、直前のアプリ出力の再取り込みを検知する。

レシピは不変の版。編集・複製には変更理由を付ける。同時編集は期待する版で検査。組み込み原本は編集できず、自分用に複製する。更新後もプロジェクトの版固定を保持する。現在の一覧には最新の版、履歴には直近200版を表示する。

任意フィードバックは対象の版と結果・メモへ紐付く。自動修正・自動送信はしない。教材は8本の候補で、具体例・理由・確認方法・限界・確認日を表示。効果・トークン削減は未検証。

JSON Exportは選択したレシピだけを含む。案件のプロジェクト・入力・利用履歴・フィードバックを含めない。Importはschema・変数・制約・教材必須項目・既存版との整合をRust側で検査し、導入内容の確認後に採用する。既存版の内容を書き換えるパックは拒否する。保存先やプランが変わった場合は再確認が必要。

## 構成と権限

- `src/features/`：オンボーディング、プロジェクト、教材、改善、合成、小窓。
- `src-tauri/src/domain.rs`：純粋な合成・検査。`application.rs`：保存とユースケース。`infrastructure.rs`：DBワーカー。`desktop.rs`：OS接続。
- `content/catalog.json`：候補教材。アプリ起動時には新しい版を自動採用しない。更新はImportで行う。
- Tauri v2の[Capabilities](https://v2.tauri.app/security/capabilities/)を使用。`allowlist`は使用しない。組み込みウィンドウだけに独自IPCを許可し、編集要求は通常画面で検査する。
- [Clipboard](https://v2.tauri.app/plugin/clipboard/)と[Global Shortcut](https://v2.tauri.app/plugin/global-shortcut/)のRustプラグインを使用。UIへファイル・HTTP・シェル・直接クリップボードのプラグイン権限を渡さない。
- 本番CSPは外部の接続先を許可しない。外部AI呼び出し・テレメトリー・自動同期・バックグラウンドの教材取得は未実装。

ブラウザの操作確認は `PROMPT_RECIPE_PREVIEW=1` 時だけのVite middlewareを使用し、同じRustコアを開発用DBへ接続する。本番アプリにはHTTPサーバーを含めない。ブラウザでは利用記録・OSショートカット登録を実施しない。
