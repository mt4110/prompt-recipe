# 製品とUX

状態：レビュー用初稿 / 2026-10-04。実装は未着手。

## 1. 製品の目的

Prompt Recipeは、AIを使ったソフトウェア開発を実践しながら学ぶ教材と、その指示をすぐ使う道具を一体にする。
利用者がレシピの適用条件・理由・検証方法を理解し、将来はレシピなしでも判断できることを目指す。

価値の仮説は、繰り返す説明、不要な資料読込、逸脱の訂正、再試行を減らすこと。モデルの能力差を消すこと、同じ性能、節約率、電力削減を保証しない。
他の主力プロダクトの進行を止める大規模な研究にはしない。日常の実依頼で価値を確かめてから拡張する。

## 3. 主要な利用者と場面

- 初級者：何をAIに渡し、どこを確認すればよいか分からない。実例から使い始める。
- 経験者：いつもの判断基準を毎回説明している。セットを案件に割り当てる。
- 新しい領域に入る開発者：前提と危険な操作を理解してから進めたい。教材の前提知識と実験境界を確認する。
- 別PC・別AIを使う人：個人ログを丸ごと移さず、汎用指示と案件内の前提を結び付ける。

## 4. 情報構造

通常画面の起動先と主な入口は「プロンプト台帳」。次に「プロジェクト」「改善の記録」を配置する。自分の台帳と組み込み教材は一覧を分け、Git対象を選ばずに名前と本文だけで登録・コピーできる。教材の更新履歴はレシピ詳細と設定から確認する。
レシピ詳細に「使う」「実例」「なぜ効くか」「適用条件・限界」「変更履歴」をまとめ、独立した学習ダッシュボードは初期版で作らない。

普段の操作は短く、説明は必要なときに開く。指示全文を常に教材解説と一緒にコピーしない。
難易度は人の評価ではなく、前提知識・変更の影響・復旧の難しさを示す。

### 日常の依頼と目的から探す（2026-10-04合意、2026-10-08実装）

レシピを探す入口は「分析する」「直す」「設計する」「相談する」の4つを初期案とする。
目的は「品質」「時間」「コスト」「理解」の任意フィルターにする。入口と目的の両方を毎回選ぶことを要求せず、目的だけの絞り込み、名前検索、保存済みセットからの直接利用も可能にする。
既存のAI比較は、利用環境と適用条件を確認する上位の案内として維持する。

| やりたいこと | 最初に求める成果物・止まる段階 |
| --- | --- |
| 分析する | 根拠付きの全体構成、処理・データの流れ、問題候補、未確認事項を報告する |
| 直す | 原因と変更案を示す。再発防止の恒久対応か、振る舞いを保つ構造整理かを区別する |
| 設計する | 正本・要求・制約との対応、選択肢、トレードオフ、推奨案を示す |
| 相談する | 論点・仮説・選択肢・次に確かめることを対話で整理する |

入口の選択だけで実装や権限変更を承認したとは扱わない。利用者が依頼した段階と既存の承認範囲を保つ。
同じレシピを複数の入口・目的から見つけられるようにし、分類のために本文や版を複製しない。領域と難易度は別の属性として保持する。
絞り込みで、選択済みのレシピや合成順を勝手に変更しない。絞り込み中も選択済みの内容を確認でき、条件を戻せるようにする。

実利用の振り返りで、目的から探す方が多く使いやすいと分かった場合は、目的を主な入口にする案を再検討する。分類を大きく固定せず、評価のための利用追跡や毎回の報告を強制しない。

## 5. 初回利用

0. AI比較を見て、渡す環境と最初の用途を選ぶ。確認日・公式情報・提案を区別し、選択は後回しにもできる。比較は利用開始後も常設する。
1. 個人用／案件内用の保存領域を選ぶ。後から分離でき、保存先を表示する。
2. 組み込みの「開発の基本」を試す。登録前でも仮入力で完成文を確認できる。
3. 必要ならプロジェクトを作り、正本の参照先と利用環境を登録する。
4. 必要なレシピだけ割り当てる。案件情報・絶対パス・認証情報を汎用セットへ混ぜない。

ログイン、外部APIキー、課金、クラウド同期を初回利用の条件にしない。
既存ツールの自動読込に任せるか、作業開始時に貼るかは出力先の設定で選ぶ。ファイルをまだ書けなくてもコピーで完結する。

## 6. 通常ウィンドウ

作業開始画面は「対象プロジェクト」「使うセット」「今回の追加」「渡す指示」で構成する。
プロジェクト選択はウィンドウ上部に常設し、小窓と共通の選択状態を使う。前面アプリや開いているディレクトリから勝手に推定しない。

セットは保存済みの割り当てを使う。チェック操作は今回だけの変更で、永続変更は「セットへ保存」で明示する。
未保存の変更を示し、保存しないで戻れる。毎回コピー前の確認ダイアログは出さず、未入力・衝突・出力先変更がある場合に必要な判断を求める。

広い画面では選択と完成文を左右に置く。狭い画面では縦に並べる。
選択変更時はレシピ名・選択件数と「プレビューを更新」を通知する。縦配置で更新された完成文が画面外の場合はそこへ移動する。
移動はIME入力中や文字入力のたびには行わない。動きの低減設定時は滑らかな移動を避け、キーボードのフォーカスを勝手に飛ばさない。
連続選択で移動が邪魔になる場合は、自動移動を無効にできる。

正本が未設定なら「参照先未設定」と示す。Prompt Recipeが資料を読んだことと、出力先のAIが読んだことは別であり、後者を成功表示しない。

## 7. 小窓

ショートカットで呼ぶ → 検索または固定順の候補を選ぶ → 必須入力がなければEnterでコピー → 閉じる。
↑↓は候補移動、Tabは入力欄移動、Escは入力から候補へ戻る／小窓を閉じる。日本語変換のEnterをコピーと解釈しない。

ピンの並びは固定。直前に使ったレシピは専用の再利用枠に置き、利用頻度で候補を勝手に並べ替えない。
小窓の上部に対象プロジェクトと利用環境を示す。管理画面へ移っても選択と未確定入力をそのセッション中は保持する。
未解決の必須入力・確定衝突がある場合は、コピーせず該当箇所を示す。

クリップボードは、利用者が機能を有効にし、そのレシピが素材を要求する場合だけ取得する。常時監視しない。
その呼び出し中は素材を固定し、プレビューに出所を表示する。再呼び出しで前回の完成文が素材になりそうなら「前回の出力」と示して取り直し／素材なしを選べる。前回の素材へ黙って戻さない。
入力素材・展開値・完成文は既定で保存しない。コピー後の元アプリへの復帰はmacOSで検証する。自動貼付と自動送信は初期対象外。

## 8. レシピの登録と教材

自分の指示は「貼り付け → 名前を付ける → 保存」で登録できる。教材の全項目を個人メモに強制しない。
組み込みレシピは閲覧専用。編集は自分用に複製し、派生元を記録する。
教材詳細では「困った場面 → 実例の成果物 → レシピ → 確認方法 → 限界」の順で見せる。
未再現の教材はその状態を明示し、検証済み教材のように見せない。

右クリック取り込みは、macOSのServicesを候補にする。全アプリの右クリックへ必ず表示されるとは扱わない。
受け取るのは利用者が選んだテキストだけ。取り込み先を確認して下書きにし、自動で案件外へ保存しない。
Services対応が難しい場合も、コピー → 登録用ショートカット → 名前 → 保存という導線を提供する。

## 9. フィードバック

コピーの成功は利用・回答成功の証拠ではない。任意で「そのまま使えた／手直しした／指示を守らなかった」を残せる。
対象はレシピの版、利用環境、用途。セット全体への報告も可能にし、原因レシピが不明なら不明のまま残す。
AIの回答・案件ログを自動収集しない。具体例の入力は任意で、保存領域を表示する。

報告 → 原因の切り分け → 修正案 → 差分確認 → 新版 → 再利用の結果、を同じ履歴で追えるようにする。
改善案はまず手動編集と外部AIに渡せる依頼文の生成で成立させる。回答の取り込みで候補版を作り、利用者が採用する。
無報告は成功とみなさない。人気や利用回数を品質の証明にしない。学習の確認は任意の振り返りで、毎回の試験や連続利用を煽る仕組みは設けない。

## 10. エラーとアクセシビリティ

| 状態 | 利用者への挙動 |
| --- | --- |
| 空のライブラリ | 組み込み教材を試す／自分の指示を登録する |
| 検索結果なし | 条件を戻す。既存の入力を消さない |
| ショートカット競合 | 通常ウィンドウは使え、別キーを指定できる |
| コピー失敗 | 小窓を閉じず、入力保持と再試行 |
| DB記録失敗・コピー成功 | コピー成功と利用記録失敗を分けて表示 |
| 教材が古い／適用環境が違う | 日付・条件・理由を表示し、適用判断を利用者に残す |
| 更新／Import失敗 | 現行版を維持し、原因と再試行を示す |

Tab順、見えるフォーカス、読み上げの選択状態と更新通知、文字拡大、日本語IME、色に依存しない警告、動きの低減を検証する。
アプリ本体では変更ごとに画面全体を再生成せず、フォーカス・入力・スクロール位置を保持する。

## 11. 初期構成と判断待ち

初期構成案：macOS優先、通常画面＋小窓、手動登録、セットと割り当て、変数、ローカル衝突検査、版付きフィードバック、教材パックの手動更新、JSON／Markdown Export。
後段：Services、CLIからの指示書更新、Windows／Linux検証、任意のオンライン更新、AIによる衝突判定補助。

判断待ち：教材・コードのライセンス、配布経路、案件領域の保存と保管期限、最初に公開する教材範囲。「フル設計」は全機能の初回実装承認ではない。

## V0.1の具体化（2026-10-08）

台帳の個人プロンプトは名前・本文を必須とし、分類・変更理由の調整・教材解説は任意。旧版の詳細を選ぶとその版をプレビュー・コピーする。名前付きセットはチェック順と版を保持する。プロジェクト画面で適用したセットは下書きで、保存したときだけ小窓の割り当てへ反映する。

新しいプロジェクトはネイティブのフォルダ選択とGit作業ツリーのルート検証で開く。既存の台帳用・旧プロジェクトを削除しない。ローカルパスはアプリ設定だけに保存し、JSONの移行対象へ含めない。

大小ウィンドウは相互に非表示へ切り替える。画面内の検索・素材・未保存状態を保つが、両画面の未保存入力を自動合成する機能ではない。Esc、OS閉じる操作、コピー成功で小窓を隠し、Dockから通常画面を復帰できる。

初回は教材を知る、素材を入れてコピーする、名前付きセットを保存する、の3段階。保存した素材をセット本文に埋め込まない。Gitプロジェクトへは後から割り当てる。初見の利用者での完了率・所要時間は未測定。

V0.1の現在の移行形式はJSON。ZIPは検査方式の設計段階、署名・公証・Windows・CLI配布と自動教材更新は判断待ち。XML文書／Markdown基本Lintは明示実行・助言だけとする。詳細と確認範囲はIMPLEMENTATION.mdとTASKS.mdを参照する。初稿の将来機能が実装済みという意味ではない。
