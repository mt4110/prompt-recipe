# AIを選んでから、レシピを選ぶ

確認日：2026-10-04。比較資料の版：2026.10.04.1。
対象は個人向け有料上位プランとソフトウェア開発。価格は地域・税・契約で異なるため、購入判断は契約画面で確認する。4社を同条件で実行した性能測定は行っていない。

## 結論と比較軸

ブランドを「性格」で固定するより、**モデル × 利用環境 × 用途 × 検証手段**で選ぶ。モデルの能力、資料へのアクセス、ファイル編集・テスト実行、並列作業の仕組みは別の条件である。最上位の契約が、常に最上位モデルでの実行や無制限利用を意味するとは限らない。

| 入口 | 今回確認したモデル・上位プラン | 任せる候補（設計上の提案、実測順位ではない） | 判断の注意 |
| --- | --- | --- | --- |
| ChatGPT / Codex | GPT-6 Astra。継続作業にはGPT-6.1 Sol。個人上位Pro $500 | 設計・実装・検証をつなぐ作業。明確な反復作業は低コスト側から | Sol/LunaはWork・Codexでの提供。通常のChatの選択肢と分ける |
| Claude / Claude Code | Fable 5.1、Opus 5.5。Max 20x | 根拠付き資料分析、状態遷移、設計レビュー、アルゴリズム。コード変更も検証環境で試す | XMLは区分の工夫。遵守保証ではない。Fableの利用枠も確認する |
| Gemini / Antigravity | 消費者向け案内は3.1 Pro・Deep Think。Ultra 20xの利用枠。API側には3.8 Flash等 | 横断調査、資料分析。開発作業はAntigravityで検証 | 消費者向け契約、APIモデル一覧、開発環境を同一視しない |

OpenAIの位置付けは[モデル資料](https://learn.chatgpt.com/docs/models)と[プラン資料](https://learn.chatgpt.com/docs/pricing)、Claudeは[モデル選択](https://platform.claude.com/docs/en/about-claude/models/choosing-a-model)・[Maxの利用枠](https://support.claude.com/en/articles/11049741-what-is-the-max-plan)と[Fableのプラン対応](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan)、Googleは[消費者向けプラン](https://gemini.google/subscriptions/)・[API一覧](https://ai.google.dev/gemini-api/docs/models)・[Antigravity](https://antigravity.google/)、GitHubは[プラン](https://docs.github.com/en/copilot/get-started/plans)と[対応モデル](https://docs.github.com/en/copilot/reference/ai-models/supported-models)で確認した。ベンダーの能力説明を独立した比較測定として扱わない。

## 独立した使い方の提案

資料分析・数学・インフラについて、今回「Claudeが他より強い」と証明できる比較結果は得ていない。ただし、出典を区分する資料分析、状態遷移や前提の明確なアルゴリズム設計は試す価値がある。失敗した並列リファクタリングも、モデルの版、実際に読めた資料、編集権限、検証ツール、承認待ち・停止条件を確認する。XMLに変えるだけでこれらが解決するとは考えない。

全モデル共通で、低レイヤーや本番インフラは対象の実行環境による検証と人の判断を必要とする。設計の読み取り失敗には「理解確認」、重複読込や高価な反復には「資源設計」、編集競合には「並列設計」のレシピを使う。数値の節約率や省エネ効果は実測するまで提示しない。

最小の比較方法は、日常の一つの依頼で、同じ正本・変更範囲・受け入れ条件を用意し、実モデル・環境・設定と、逸脱・手直し・テスト結果を任意で記録すること。各社を毎回試すことや全社の契約を利用条件にしない。メーカーを跨ぐ序列や恣意的なスコアは表示しない。

## 実装と更新の境界

- AIガイドはオンボーディングより上の入口。あとで選ぶことも可能。通常画面と初回案内に「AIを比較・選択」を常設する。
- `content/ai-profiles.json` にモデル・プラン・用途提案・注意・公式出典・確認日・版・次の確認目安を保持する。約1か月後の目安は運用上の再確認期限であり、その期間の正確性保証ではない。
- AI・環境・用途・形式をプロジェクトごとのSQLite設定に保存。プロジェクトの利用環境も同じトランザクションで更新する。既存の参照先・レシピ割り当ては保持する。
- 完成文はRustで環境・目的を追加し、Markdown/XMLに整形する。XMLの本文はエスケープする。タグによるセキュリティ保証はしない。クリップボードの素材を再展開しない。
- コピーは同じRust処理で再合成し、選択情報を含むhashで変更を検出する。未入力・衝突・実行不可の検査を維持する。
- 同梱資料は照合時点のスナップショット。実行時の最新取得・バックグラウンド通信・AIへの接続・モデル切替は行わない。外部リンクは利用者が参照するための出典である。
- 更新は現時点ではソースの教材ファイルをレビューしてアプリを再ビルドする。レシピのJSON ImportとAIガイドは別の形式であり、AIガイドの実行時Importは未実装。

次段階では、公式ページの変更を取得して**更新候補と差分を作る**工程を検討する。情報が取得できない場合は旧確認日を維持し、最新扱いしない。人がモデル・プラン・適用条件と出典を確認して採用する。GitHub Actions/Cloudflareへの配置や定期実行、公開は今回行っていない。無査読の生成文を組み込み教材へ自動採用しない。
