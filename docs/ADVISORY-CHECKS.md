# コピー前のローカル検査

2026-10-28実装。検査はRust内で行い、ネットワーク・常駐サービスは使いません。

## 方式と判断

既存のveil-rs RulePackはTOML・複数ファイル・重複IDを含むため、全エンジンを取り込まず、必要な9ルールのIDと正規表現をJSONへ変換して同梱します。元はローカルveil-rs commit `83592f5cfb73059f3eaadefcb98bb38262f2ff78` の `crates/veil/rules/default/{cloud_keys,secrets,pii,pii_jp}.toml`。MITを選択し、`content/VEIL-RULES-LICENSE-MIT` を同梱します。変換は `python3 scripts/import-advisory-rules.py /path/to/veil-rs`。実行時に元リポジトリは不要です。

「外部依存を追加しない」と検出ルール利用の両立は、すでにCargo.lockに存在するregex 1.13.1を直接利用することで解決しました。新しいパッケージやサービスは追加していません。ルールエンジン全体との同等性は主張しません。

追加ルールはAPIキー形式、秘密鍵ブロック全体、SECRET/TOKEN/PASSWORD代入、JWT、接続文字列、メール、電話番号、Luhn検証付きカード番号、チェックディジット付きマイナンバーです。重なる検出範囲を統合し、UTF-8 byte範囲を逆順でマスクします。画面ではbyte範囲を文字列へ戻してハイライトします。マスクは末尾を残さず `[MASKED]` に置換します。

## コピーと保存

プレビュー更新時はデバウンスして検査し、コピー直前にもRustで検査します。デスクトップでは再合成・ハッシュ照合後にマスク処理を行います。通常ボタンはマスク、別ボタンは明示的な「そのままコピー」です。構造化制約・未入力・ハッシュ不一致による既存の停止は維持します。

検出値をログ・SQLite・履歴へ書きません。検出はメモリのみで、件数やルールIDも現時点では永続化しません。コピー履歴には版IDだけを渡します。利用者が本文として明示保存したプロンプトは従来どおり平文保存です。

「このプロンプトでは無視」は、版IDの組合せとルール・値のSHA-256ハッシュだけをWebViewのローカル保存へ記録します。入力値そのものは記録しません。ただしハッシュは暗号化や匿名化の保証ではなく、短い番号等は推測可能です。保存する検出値の種類を限定し、共有端末の利用には注意してください。本文・入力値はローカル保存の無視設定には含めません。

## 限界と検証

このアプリを通した文章だけを検査します。未知形式・難読化・意味・正当性を検査せず、誤検知と見逃しがあります。DLPではありません。カードやマイナンバーのチェックディジット一致も実在の証明ではありません。

2026-10-28のローカルmacOS ARM64、Rust debugテストで10,000文字を走査した実測は15,607µs、1検出でした。ルール初期化が混在し得る単発値であり、全端末の上限・応答保証ではありません。プレビュー全体の時間や本番配布バイナリの性能とは区別します。

Rustテストで同梱9ルールのダミー陽性・陰性、チェックディジット、秘密鍵全体・重複・Unicode、マスクの固定結果、検査リクエストによるDB変更なしを確認します。ブラウザ検証は一時DBとダミー値を使用し、通常コピー／マスクコピーを確認します。OSクリップボード・グローバルショートカット・Windows実機の全経路は別途実機確認が必要です。

## 画面確認の記録

2026-10-28、`http://127.0.0.1:1420`、一時DB `/tmp` を使い、Chrome headless + Playwrightで確認。Browserプラグインが利用可能なスキル一覧にないため、既存のPlaywrightとインストール済みChromeを使用しました。依存やブラウザの追加インストールはしていません。

- 初回登録 → 入力 → コピー、本文の完全一致
- 新規登録 → ダミーの秘密値・メールの検出 → マスク出力に値が残らないこと
- そのままコピーの明示選択
- タブを跨ぐチェック → 別行の詳細表示 → 選択保持
- 小窓の検索 → Enter → 入力 → Ctrl+Enter → 出力一致と自動で閉じる動作
- ページタイトル、空画面・フレームワークエラーがないこと、pageerrorなし
- 1440×1000、390×844でスクリーンショット確認。狭幅のヘッダー重なりを修正

これらの回帰シナリオのクリップボードはページ内スタブで隔離し、OSで作業中のクリップボードと競合させません。ブラウザで渡される最終文字列を検証しており、macOSネイティブのクリップボード実機確認と同一ではありません。

小窓と台帳の同時リクエストでプレビューDB初期化が競合したため、SQLite busy_timeoutを5秒に設定。既存DBの削除や初期化し直しは行っていません。

## 2026-10-28 追加修正：誤検知と検査失敗

数字だけの識別子と電話・カード番号を区別するため、電話候補は日本の桁数に加え、電話・TEL等の同一行ラベル、区切り、または+81表記を必要とします。カード候補はLuhn一致に加え、カード・credit・PAN等の同一行ラベルを必要とします。`0312345678` や裸のLuhn一致16桁は、それだけでは警告しません。これは意味の判定ではなく、ラベルのない実際の番号を見逃す範囲が増えるトレードオフです。秘密鍵・APIキー等の検出条件は変更しません。

`check_text` の失敗を、構造化制約や未入力と同じ停止理由にしないよう修正しました。プレビュー検査の失敗時は「未検査でそのままコピー」を明示します。ブラウザのコピー直前検査が失敗したときも、原文の再試行を明示的に選べます。原文コピー経路は検査エンドポイントに依存せず、Rust側でも原文コピー時に不要なパターン検査は行いません。コピー直前の再合成・未入力・衝突・ハッシュ照合は維持します。自動で原文へ切り替えてコピーする動作ではありません。

Chrome headlessで `check_text` エラーを注入し、プレビュー検査失敗後の原文コピー、コピー直前検査失敗後の明示的再試行、その際の検査呼出し不要、未入力による停止維持を確認しました。クリップボードはページ内スタブで確認しています。さらに、ラベルなし数字で警告しないことと、ラベル付き番号をマスクできることを確認しました。

このMac環境では `cargo build --manifest-path src-tauri/Cargo.toml --bin prompt-recipe` が成功し、`desktop.rs` を含む実行ファイルのコンパイル・リンクまで確認しました。アプリを起動してのOSクリップボード・グローバルショートカット試験、および他環境でのビルドを確認したものではありません。
