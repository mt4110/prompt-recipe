# ローカル導入とBuilt-in昇格

作成日：2026-10-10。これは手順書であり、利用者のMac・Global・SQLiteへ適用した記録ではない。

## 今すぐ使う範囲

1. `content/packs/resource-efficiency.json`をアプリの「台帳・セットをImport」で選ぶ。
2. 差分と本文を確認して導入し、「省資源」で検索する。必要なものだけコピー・セット保存する。
3. 個人の希望は別の台帳レシピへ書く。公開ファイルへホームディレクトリ、秘密、案件情報を入れない。

このパックはschema 2 / `builtin: false`の任意導入教材。既存の選択・プロジェクトへの割当・固定版を自動変更しない。
レシピの登録とエージェントへの適用は別操作であり、ImportしてもGlobalへの書込みは起きない。

## Globalを適用するローカルワーカーへの依頼

以下は対象Macへアクセスできるワーカーで実施する。別マシンのHOMEを編集して代行完了としない。

```text
目的：共有の省資源契約を、現在利用しているCodexのGlobal指示へ重複なく統合する。

1. 作業ツリーの状態と指示書を読み、既存・未コミットの変更を保護する。無断でreset、stash、checkout、mergeしない。
2. 実際のCODEX_HOMEを確認する。既定は ~/.codex。AGENTS.override.mdの非空ファイルが有効なら、その優先関係と管理元を確認する。
   .agent、AGENT.md、AGENTS.md、CLAUDE.md等を同一視しない。他エージェントの設定は今回まとめて変更しない。
3. 有効なGlobalの既存内容、symlinkの行き先、所有・権限をローカルで確認する。秘密や全文を公開リポジトリ・PRへ出さない。
4. 元ファイルをアクセス制限したローカル領域へ日時付きでバックアップする。読み取り専用・競合・管理元不明なら書込み前に止める。
5. docs/examples/AGENTS.resource-efficiency.mdを読む。既存の節約ルールと意味・対象範囲を照合して統合する。
   無関係な既存ルールと承認境界は保持する。開始・終了マーカーが既にあれば同じブロックを重ねない。
   マーカーが重複・破損していたら機械的に追記せず確認する。より厳しい制約を無断で緩和しない。
6. 長いハンドブックや9本の本文をGlobalへ全部貼らない。必要なら実在を確認した詳細文書の参照先だけを添える。
7. 書込み直前に元ファイルが変わっていないか再確認し、安全に保存する。失敗時は元ファイルを維持する。
8. 差分・重複・権限・参照先をローカルで検査する。既存の料金、モデル、安全確認、通信、sandbox設定は変更しない。
9. 新しいCodexセッションで有効な指示の読込みを確認する。自己申告だけで全動作の遵守を保証しない。
   有料の確認呼出しは通常の利用枠・承認規則を守る。認証情報を含むログを公開しない。
10. 実際に編集したパス、バックアップ先、統合要点、確認済み/未確認を報告する。
```

Codexの探索規則は[公式AGENTS.mdガイド](https://developers.openai.com/codex/guides/agents-md)を利用時点で再確認する。
本PRにはGlobal書込み用の自動インストーラを含めない。未読の既存指示を壊す自動追記より、ローカルで内容を照合する一度の統合を優先する。

## 将来、アプリへBuilt-inとして同梱する場合

同梱と常時適用を区別する。Built-in一覧に存在しても、利用者が選択しない限り合成やGlobal変更をしない。

- 既存 `content/catalog.json` と重複する教材を精査し、単に9本を二重登録しない。
- 本パックをImport済みのDBを考慮する。`builtin`等の内容を変えるなら同じrevision_idを改変せず、新しいrevision_idと親版を定義する。
- `application.rs` の初期化、現行Catalog、旧版保持、Import、個人派生、固定版・セットの扱いを確認する。
- 新規DB、既存DB、先にImportしたDB、個人編集後、再起動、旧版固定、再Importを回帰検証する。
- 任意の教材に「自動採用」「Global自動書込み」「外部通信」を追加しない。
- 実機で検索・表示・コピー・セット保存を確認してから採用する。削減効果の検証とは分けて記録する。

## 検証コマンド

```sh
node --test scripts/resource-efficiency.test.mjs
npm run test:discovery
npm run test:core
npm run build
npm run check:boundary
```

最初はパックの静的検査。Rust側のImport・合成とmacOS実機の操作確認は別途必要であり、静的PASSで代替しない。
既存の必須検証は維持する。特定のネイティブ操作やGlobal適用を、未実施のまま完了扱いしない。
