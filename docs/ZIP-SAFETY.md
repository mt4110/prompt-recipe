# ZIP共有と検査の境界

2026-10-08。設計のみ。現在のUIはJSONだけを取り込む。ZIP解凍・スキャン・検査ツール導入を行ったとは表示しない。

共有の正本はschema 3のJSONパック。ZIPを実装する場合、原則として単一の`prompt-recipe.json`だけを許可する。実行ファイル、スクリプト、リンク、入れ子ZIP、暗号化、絶対パス、`..`、重複パス、未知ファイル、展開後1 MiB超、圧縮率やヘッダーの異常を拒否する。ディスク展開せず有界のメモリ内で検証し、中身を実行しない。ZIPサイズと圧縮率の具体上限は採用ライブラリの検証と一緒に決める。

形式検査とマルウェア検査を別に扱う。スキャンは利用者の端末内だけで行い、パックを外部サービスへアップロードしない。候補は既存のローカル検査エンジンを明示的に利用する方式。採用前に対応OS、署名更新経路、ライセンス、常駐・CPU負担、タイムアウト、終了コードと検査範囲を確認する。現時点でエンジンは未選定。

結果は「検出」「未検出」「検査不能・失敗」を区別する。検出・検査不能・失敗ではZIPを導入しない方針を初期案とし、実装前に確定する。未検出はマルウェア不在の保証ではない。検査済みという表示にはエンジンと定義の版、日時、対象hash、成否を必要とする。定義が古い場合はその事実を示す。

台帳への反映は形式検査、スキャン、本文・変更差分の確認後のトランザクションだけ。本文のプロンプト注入や危険な依頼は別問題で、スキャナーで安全と断定しない。Imported本文をアプリ自身への命令として実行しない。

次の判断はローカル検査エンジンの方式と導入負担。ツール導入、ネットワーク更新、ZIP機能の実装はこの文書だけで承認されたことにしない。
